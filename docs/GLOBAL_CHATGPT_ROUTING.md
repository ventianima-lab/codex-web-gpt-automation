# Shared ChatGPT routing

New work follows [the common automation policy](AUTOMATION_POLICY.md).
Projects reference that policy instead of copying mode-specific instructions.
This document does not authorize changing a host's global configuration.

Use one mission-based execution flow. Planning, research, review, and editing
describe the requested work, not separate engines or mandatory stage chains.
Select the requested model and effort; preserve the configured native commander
and user-approved delegation. Do not restore removed CGW routing.

The default Oracle compatibility route explicitly selects Latest, then Pro
(observed as 6 Pro). Do not numerically select GPT-5.6 to obtain Pro. Use
temporary chats with personalization automatically enabled before submission. Preserve the same
owned tab through capture, persist the complete result, and only then close it.
On uncertainty recover the same run; never automatically resend.

There is no per-project or daily qualification chain, required audit nonce,
three-receipt sequence, compulsory final marker, or archive/restore stage.
Root access, authentication, task ownership, actual model selection, and durable
result capture remain essential. Project tests and domain safety rules remain
in force.

Historical modes and recovery records retain their original meaning. They are
not advertised or selected for new work and are never automatically adopted.
