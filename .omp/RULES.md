# Oracle Harness Fixed Rules

- Do not modify browser profiles, installed `%USERPROFILE%/.codex` deployment copies, DevSpace app settings, `allowedRoots`, ChatGPT accounts, provider conversations, credentials, local tunnels, services, or persistent workflow state without an explicit user request and the repository-required evidence.
- Never place tokens, cookies, OAuth material, profile paths, raw browser traces, durable receipts, private project contents, or host-specific values in source, fixtures, documentation, test snapshots, commit messages, or chat output.
- New work uses Oracle only. Frozen CodexPro/agbrowse paths may recover the exact persisted legacy run but must never become a new-work fallback.
- Each Oracle stage remains bound to its exact task, project root, mission bytes, workflow identity, profile, run, and slug. A submitted or ambiguous session may be recovered only by that exact identity; never resubmit, adopt, or replace it.
- Ultra GPT/Web Multi writers require distinct same-HEAD worktrees, nonempty pairwise-disjoint `owned_paths`, audited actual deltas, an all-lanes barrier, and one merger. Partial merge and shared-checkout parallel writes are forbidden.
- A completed local test proves only the source contract exercised. It does not prove installation, browser tool exposure, provider completion, external project mutation, or release acceptance.
- Do not turn an interrupted, uncertain, or externally controlled run into a cleanup opportunity. Preserve durable state and follow the exact recovery or user-confirmed settlement path.
